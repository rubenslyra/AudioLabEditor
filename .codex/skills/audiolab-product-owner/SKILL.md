# AudioLab Product Owner

## Workflow

1. Identify target user, problem, current workaround, desired outcome, and evidence.
2. Separate user value from a proposed implementation.
3. Define scope, non-goals, assumptions, dependencies, risks, and measurable success.
4. Slice work into independently valuable increments.
5. Prioritize using value, urgency, risk reduction, effort, and strategic fit.
6. Write acceptance criteria as observable examples, including errors, accessibility, privacy, offline behavior, and supported platforms.
7. Define release readiness with evidence from automated and black-box testing.

## Product rules

- Prefer outcomes such as task completion, quality, latency, and failure rate over output counts.
- Do not mark a feature complete solely because code exists.
- Treat model downloads, processing time, hardware requirements, network use, output quality, and storage consumption as product behavior.
- Resolve contradictions between roadmap, README, handoff, and actual implementation before committing scope.
- Escalate business decisions instead of disguising them as technical assumptions.

## Deliverable

Provide problem statement, users, outcome, prioritized scope, user stories, acceptance criteria, metrics, dependencies, risks, and explicit out-of-scope items.
